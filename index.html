GESTURE BASED CONTROLLER FOR FILM DRONE

University of Canterbury - Computer vision research project

Developed a human-drone interaction (HDI) based controller for a DJI Tello drone that can be operated with hand gestures and body movements, aiming to design a more intuitive control method.

  • Combined geometric body pose tracking and hand gesture recognition to provide instructions to a DJI Tello drone.
  • Only required a laptop to operate, allowing for a simple setup process and reducing potential cost.
  • As part of this project, I wrote an IEEE conference style paper (unpublished) detailing the development and results of my approach against other similar works.
  • Gesture recognition achieved an accuracy comparable to other similar papers without the need for training data.
  • Control method allowed for greater flexibility as there was no requirement to retain a model when adding new gestures.

Build process:

This project was undertaken as a computer vision research project; at the start of this project, I experimented with a range of tools to detect hands, as I knew I wanted to do hand gestures to control the drone. From this experimentation, I determined MediaPipe best fit the requirements of what I was planning to do. After making this decision, I developed a gesture recognition algorithm and some basic pose-tracking functionality and mapped them to the controls I planned to use.

From here, I began working on physical drone control, testing its SDK functionality and deciding on the best path for me to implement my control logic. After deciding on what SDK functions worked for my project, I implemented them into my program along with basic proportional error controllers and some safety features such as a limit as to how close the drone was to the operator.

I then encountered some issues with the main program progress as outlined in “What challenged me”, but once I sorted this, I finished implementing the instructions until I was happy with the control set the drone had and began testing the drone with a set routine to test its performance against other drone gesture controllers I found during my literature review.

What challenged me:

The primary challenge I encountered when developing this project occurred when I began transferring the program from running on a laptop test environment to controlling a physical drone, as the three main operations the program had to preform, video feed streaming, hand and body pose processing and drone instruction calculations began to interrupt each other, causing undesirable behaviour such as the video feed freezing or instructions requiring large times to take effect. This led me to learn about concurrency software practices and implement threading into my project, running each core task on a separate thread, resulting in the drone program operating stably at 15fps and with quick response times, allowing for real-time control.

What I learnt:

Working on this project helped me develop skills in drone control logic, human-machine interaction, multi-sensor integration, concurrent software practices, live drone video processing, and conducting literature reviews.

LIGHTWEIGHT SLAM PATHFINDING AND NAVIGATION

University of Canterbury

Built a lightweight simultaneous localisation and mapping (SLAM) algorithm in C to run on a Teensy 4.0 microcontroller. This algorithm was designed for an autonomous robot to navigate an arena, collect targets, and return to its starting point when full.

  • Operated locally on the limited resources of a Teensy 4.0 microcontroller.
  • Used a weighted map and an A* algorithm to plan efficient paths while avoiding being close to walls and obstacles.
  • Combined multiple sensor inputs (time-of-flight, wheel encoders) to construct a map of the arena and track the robot's position on the map.
  • Could operate with a only single time-of-flight sensor as was the case in the video.

Build process:

I began this project by looking into Robot Operating System (ROS) as I planned to isolate the features of ROS that my team wanted for our project and code lightweight versions of them tailored to our robot's needs. I began by connecting a TOF sensor and servo to use as a makeshift “radar” module and mapped the distance readings to a 2d array, counting how many times that map point was also detected. This provided the basic map that I used to start working on the pathfinding algorithm.

For the pathfinding algorithm I looked at a variety of algorithms but decided to implement A* search as it would have better performance as I could terminate the algorithm early due to it giving preference to “better nodes”. Once the basic pathfinding was working (Fig 1), I updated the map generation to make nodes near walls more expensive to the algorithm to prevent the robot from going near walls unless necessary (Fig 2).

For the navigation I developed a pure pursuit controller that would follow the coordinate list provided by the A* algorithm. Finally, I combined the positional information provided by the wheel encoders and IMU with the coordinate map to allow the robot to move around the arena while continuously updating the map.

What challenged me:

The primary challenge I faced on this project occurred during the development of the localisation software, as testing revealed the information provided by the encoders used to track the robot was not reliable, as while themselves were accurate enough, the tracks slipping on the wheels caused the robot's position to drift over time. This caused the robot to lose track of its position and create false obstacles on the navigation map. I tried to overcome this by using readings from the IMU to determine when the robot was actually moving, which did improve the performance; however, the error still built up, leading me to begin developing a free wheel, which would have provided a better estimate of how the robot's position changed, but I was not able to implement this within the project completion deadline.

What I learnt:

Working on this project helped me develop skills in simultaneous localisation and mapping (SLAM), algorithm development and optimisation, robot pathfinding and robot navigation.
